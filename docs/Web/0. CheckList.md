## Reconnaissance

- [ ] Scan nmap
- [ ] Vérifier `robots.txt`, `sitemap.xml`, `security.txt`, `/.well-known/`
- [ ] Inspecter le source HTML pour les commentaires et données sensibles
- [ ] Chercher des secrets hardcodés dans les fichiers JS (clés API, tokens, endpoints internes)
- [ ] Fingerprinting : framework, version, CMS via headers HTTP, cookies, HTML
- [ ] Recherche de vulnérabilités (nikto, nuclei, exploit-db, etc.)
- [ ] Chercher des fichiers exposés (gobuster, fuzz) (`.bak`, `.zip`, `.env`, `.git`, `.svn`, `config.json`, `web.config`)
- [ ] Vérifier que le directory listing est désactivé
- [ ] Identifier les interfaces admin exposées
- [ ] Métadonnées EXIF non supprimées des images/documents téléchargés
- [ ] Explorer manuellement le site avec Burp

## Error handling

- [ ] Access custom pages like /whatever_fake.php (.aspx,.html,.etc)
- [ ] Add multiple parameters in GET and POST request using different values
- [ ] Add "[]", "]]", and "[[" in cookie values and parameter values to create errors
- [ ] Generate error by giving input as "/~randomthing/%s" at the end of URL
- [ ] Use Burp Intruder "Fuzzing Full" List in input to generate error codes
- [ ] Try different HTTP Verbs like PATCH, DEBUG or wrong like FAKE
- [ ] Vérifier que les pages d'erreur ne révèlent pas de stack traces, chemins ou versions

## Transport Security

- [ ] HTTPS sur toutes les pages sensibles (login, register, reset/change password)
- [ ] Absence de mixed content (ressources HTTP sur pages HTTPS)
- [ ] Header HSTS présent et correctement configuré
- [ ] Absence de protocoles TLS dépréciés (SSLv2, SSLv3, TLS 1.0, TLS 1.1)
- [ ] Absence de cipher suites faibles ou d'export
- [ ] Certificat valide, clé ≥ 2048 bits, signature SHA-256+

## Authentification

- [ ] Test avec des credentials par défaut
- [ ] Énumération de comptes via les différences de réponses
- [ ] Verrouillage de compte après tentatives répétées (brute-force)
- [ ] Politique de mot de passe (longueur minimale, complexité, mots de passe communs refusés)
- [ ] Autocomplete désactivé sur les champs sensibles (mot de passe)
- [ ] SQL injection sur le formulaire de login
- [ ] Bypass d'authentification (parameter tampering, manipulation de réponse)
- [ ] Prédictibilité des session IDs
- [ ] "Remember Me" : token chiffré et validé côté serveur
- [ ] Cache navigateur sur les pages sensibles (headers `Cache-Control`)
- [ ] Check unsubscribe button with user enumeration

### Password reset
- [ ] Token aléatoire, unique et non prédictible
- [ ] Token expiré après utilisation et après inactivité
- [ ] 2 instances open, 1st change or reset password, refresh 2nd instance
- [ ] Rate limiting sur les demandes de reset
- [ ] Host header injection pour empoisonner le lien de reset
- [ ] Fuite du token dans le header Referer
- [ ] IDOR dans le lien de reset (manipulation de l'ID utilisateur)
- [ ] Énumération de comptes via les différences de réponses
- [ ] User carbon copy email=victim@mail.com%0a%0dcc:hacker@mail.com

### Password change
- [ ] Ancien mot de passe requis pour changer
- [ ] Les autres sessions actives sont invalidées après le changement

### JWT
- [ ] Algorithme "none" accepté
- [ ] Bypass de vérification de signature
- [ ] Données sensibles dans le payload JWT

### OAuth / SSO
- [ ] Paramètre `state` absent ou non validé (CSRF)
- [ ] Gestion incorrecte des scopes OAuth
- [ ] Implémentation SSO/SAML non sécurisée

- [ ] Brute-force OTP
- [ ] Réutilisation d'OTP (même code soumis deux fois)
- [ ] OTP expiré toujours accepté

## Logique métier

- [ ] Manipulation de prix ou quantité (valeurs négatives, zéro, overflow)

- [ ] Réutilisation ou cumul de codes promo/réduction
- [ ] Abus de parrainage ou bonus
- [ ] Accès à des fonctionnalités cachées ou non publiées
